# Plan 4: Admin app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `apps/admin`, the private admin app that will run at `admin.<domain>`. With it the owner can sign in, edit the site content, manage invites and what each one shows, read the visits timeline and overview, and mark his own devices. It consumes only the routes from Plans 1 and 2.

**Architecture:** React 19 + Vite 8 SPA with MUI 9, react-router 8 and TanStack Query. All HTTP goes through `apiFetch`, so tests stub `fetch` with a route table (`mockApi`). Pure logic (visibility tri-state, browser-timezone times, device grouping) lives in plain TS modules tested without React. Client validation reuses `@pf/shared`'s Zod schemas (allowed here, unlike the site).

**Tech Stack:** React 19.3, Vite 8.3 + @vitejs/plugin-react 6.3, TypeScript ~6.0.3, @mui/material 9.5 + @mui/icons-material 9.5 + @emotion/react 11.14 + @emotion/styled 11.14, react-router 8.5, @tanstack/react-query 5.107, qrcode 1.5 (+ @types/qrcode 1.5), Vitest 5.1 + jsdom 31 + @testing-library/react 16.3 + @testing-library/user-event 14.6 + @testing-library/jest-dom 7.0, eslint-plugin-react-hooks (same version as Plan 3).

**Spec:** `docs/superpowers/specs/2026-11-11-portfolio-design.md` (section 5 "Admin v1", "Visits", tracking rules). Builds on `2026-11-11-plan-1-api-foundation.md`, `2026-11-11-plan-2-tracking.md` and `2026-11-11-plan-3-site.md` (tooling conventions).

## Reconsider before executing

Nothing below is approved yet. The owner answers each before Task 1.

1. **MUI 9, not something lighter:** the owner knows it from A-Store, the admin is private (bundle size barely matters), and tables, dialogs and switches come ready-made. Rejected: plain CSS like the site (far more form/table code), shadcn/Tailwind (a new toolchain mid-infra).
2. **MUI's CSP cost:** Emotion injects runtime `<style>` tags, so the admin host needs `style-src 'self' 'unsafe-inline'` (`script-src` stays strict). A per-response nonce doesn't fit a static build. Feeds Plan 5's admin `nginx.conf` block.
3. **TanStack Query over hand-written hooks:** ~14 endpoints with refetch-after-mutation everywhere; hand-written hooks would rebuild its cache.
4. **No form library:** controlled state + the shared Zod schemas' `safeParse`, issue paths mapped to field errors.
5. **"Include my devices" lives in the URL** (`?mine=1`), not storage.
6. **Mark-link QR** via `qrcode`, for phones. In dev the link points at `localhost:5173`, so only "open on this computer" works locally.
7. **Dev `.env` needs `PUBLIC_SITE_URL=http://localhost:5173`**, or invite and mark links point at the `yourname.dev` placeholder (a Plan 1 `.env.example` note, not code).
8. **No Playwright here:** e2e needs a real Postgres; Task 8 is a manual smoke run. Add it after Plan 5's Compose if wanted.
9. **No Safari 14 pin:** Vite's default target; only the owner's browsers load the admin.
10. **Day groups only:** `OverviewDto` has no time buckets (Plan 2 dropped visits-by-hour), so "browser timezone" covers the timeline's day groups and every displayed time.
11. **Nice-to-have Plan 1/2 changes, not required:** a `kind` on `Link` (Plan 3 item 3); `GET /api/admin/invites/:id` (the edit page reads the cached list instead).
- Plan 1 now ships `Link.kind` (approved 2026-11-11): use it instead of the hostname guess; Plan 4 can use `GET /api/admin/invites/:id`.

## Global Constraints

- **Plans 1–3's Global Constraints still apply:** executors never run `git commit` or `git push`; no Dockerfile, Compose or `nginx.conf`; the version pins; the error JSON shape `{"error": "<snake_case>", "issues"?: [...]}`.
- **Package:** `@pf/admin` (`apps/admin`, private), with `"@pf/shared": "workspace:*"`. Runtime imports from `@pf/shared` are allowed.
- **tsconfig and lint as Plan 3:** `module: "preserve"`, `moduleResolution: "bundler"`, `jsx: "react-jsx"`, `lib: ["ES2023","DOM","DOM.Iterable"]`, `noEmit`, `types: ["vite/client"]`, extensionless relative imports; `eslint-plugin-react-hooks` recommended for `apps/admin/**/*.{ts,tsx}`.
- **Dev server:** port `5174`, `strictPort`, proxy `/api` → `http://localhost:3000`, and `resolve.conditions: ['development', ...defaultClientConditions]` in every mode.
- **noindex:** `index.html` has `<meta name="robots" content="noindex, nofollow">`. It has no inline script or style.
- **Same-origin only:** every request is a relative `/api/admin/...` path with `credentials: 'same-origin'`. The `sid` cookie (Plan 1: `Path=/api/admin`, host-only, httpOnly) is never read by JS.
- **Fonts:** system font stack set in the MUI theme. No Roboto download.
- **Times:** the API sends UTC ISO strings. Every displayed time goes through `src/lib/time.ts` with the browser's timezone (`Intl.DateTimeFormat().resolvedOptions().timeZone`). No date library.
- **UI copy (exact):**
  - Login 401: `Wrong password or code.`
  - Login 429: `Too many failed attempts. Sign-in is locked for 15 minutes.`
  - Login network error: `Can't reach the API.`
  - Login 400 (or a client-side check fails): `Enter your password and a 6-digit code or a recovery code.`
  - Delete dialog: title `Delete invite "<label>"?`, body `This also deletes all of its visits and events. This can't be undone.`, buttons `Cancel` and `Delete`.
  - Visibility tri-state labels: `Default`, `Show`, `Hide`.

## Review Focus

1. **A 401 anywhere returns to sign-in.** When a query or a mutation gets 401 (the session expired mid-use), the app clears its cache and shows `/login`, and after signing in returns to the page it was on. Tests: Task 2.
2. **Locked is not "wrong password".** A 429 shows the lock message, never `Wrong password or code.`, and the password field keeps its value. Tests: Task 2.
3. **Delete needs a confirm.** Clicking Delete sends nothing; only the dialog's `Delete` button sends `DELETE /api/admin/invites/:id`, and `Cancel` sends nothing. Tests: Task 4.
4. **Visibility overrides round-trip exactly.** Opening an invite with `{ sections: { stack: false }, channels: { whatsapp: true } }` and saving without changes sends that exact object. Setting an item to `Default` removes its key, and an emptied group is removed (`{}`, never `{ sections: {} }`). Tests: Task 4.
5. **Times are shown in the browser timezone.** `2026-11-10T23:30:00Z` shows as 11 Nov in `Asia/Tokyo` and 10 Nov in `America/Los_Angeles`, and visits group into those local days. Tests: Task 5.
