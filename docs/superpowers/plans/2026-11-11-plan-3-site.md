# Plan 3: Public site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `apps/site`, the public one-page portfolio. It renders only what `GET /api/site?code=X` returns, greets invited visitors, sends the tracking beacon defined in Plan 2, and builds to static files that parse on Safari 14.

**Architecture:** React 19 + Vite 8 static SPA with no router: `parseLocation()` reads `/` or `/c/<code>`, and `main.tsx` starts the payload fetch before React renders. Only sections present in the payload are rendered, so hidden content never reaches the DOM. A plain-TypeScript `Tracker` owns all beacon logic and is tested without React. Plain CSS with cookbook tokens; scroll effects A–H come in a later plan.

**Tech Stack:** React 19.3, Vite 8.3 + @vitejs/plugin-react 6.3, TypeScript ~6.0.3, Vitest 5.1 + jsdom 31 + @testing-library/react 16.3 + @testing-library/user-event 14.6 + @testing-library/jest-dom 7.0, @playwright/test 1.65, browserslist-to-esbuild 2.1, acorn 8.19, eslint-plugin-react-hooks 7.1.

**Spec:** `docs/superpowers/specs/2026-11-11-portfolio-design.md` (section 5, public page and tracking). Builds on `2026-11-11-plan-1-api-foundation.md` and `2026-11-11-plan-2-tracking.md`, and uses the cookbook, compatibility and known-traps parts of the original Nov 8 build spec (values copied below).

## Review Focus

1. **Hidden means not rendered at all.** A payload without `phone` or `whatsappUrl` produces no `tel:` or `wa.me` link and no empty "Phone" label. A payload without `stack` has no `#stack` element and no progress dot for it. Tests: Task 6 (unit) and Task 8 (e2e).
2. **`start` first, exactly once, after `/api/site` answers.** The `dk` cookie comes from that response. No `reached`, `enter` or `click` beacon goes out before `start`. Test: Task 5.
3. **The source tag is stripped on the first interaction, not on mount.** `/c/K7M-4QX?s=qr&x=1` keeps `?s=qr` until the first pointerdown, keydown, wheel, touchstart or scroll, then becomes `/c/K7M-4QX?x=1` with the hash kept. Test: Task 2.
4. **Reduced motion is a still, fully visible page.** Under `prefers-reduced-motion: reduce`, the hero's computed `animation-name` is `none` and its opacity is `1` at first paint. Test: Task 8.
5. **No horizontal scroll at 360 px.** A long email, a long project name and the compare slider all fit: `document.documentElement.scrollWidth ≤ clientWidth` at 360×740 in Chromium and WebKit. Test: Task 8.

### Task 4: Tracker (reached, enter, click, active time)

**Files:**
- Create: `apps/site/src/track/{tracker.ts,device.ts}`
- Test: `apps/site/test/tracker.test.ts`, `apps/site/test/fake-io.ts`

**Interfaces:**
- Consumes: `sendBeacon`, `uuidv4`, `TRACK_TARGET_RE` (Task 3); `import type { BeaconEvent, SourceTag, TrackSection } from '@pf/shared'` (Plan 2 Task 1).
- Produces:
  - `deviceType(win: Window): 'phone' | 'tablet' | 'desktop'`: coarse pointer (`matchMedia('(pointer: coarse)')`) and `min(screen.width, screen.height) < 600` → phone; coarse otherwise → tablet; else desktop.
  - `type TrackerOptions = { code: string | null; source: SourceTag | null; send?: (ev: BeaconEvent) => void /* default sendBeacon */; now?: () => number /* default performance.now */; win?: Window; root?: Element | null /* IO root, null = viewport */ }`
  - `type Tracker = { visitId: string; start(): void; observe(el: Element, section: TrackSection): () => void; click(target: string): void; onActiveChange(cb: (s: TrackSection | null) => void): () => void; destroy(): void }`
  - `createTracker(opts: TrackerOptions): Tracker`, with these rules:
    - `visitId = uuidv4()`, created once per page load.
    - `start()` sends `{ k:'start', v, code?, s?, tz?, ref?, dt, sw, sh }` once. Optional fields are omitted when empty or invalid: `tz` from `Intl.DateTimeFormat().resolvedOptions().timeZone` only if it matches `/^[A-Za-z0-9_+\-/]{1,64}$/`; `ref` is `document.referrer` cut to 500. `sw`/`sh` are `screen.width`/`screen.height`, clamped to 0–10000.
    - **Queue:** any event produced before `start()` is held and sent right after `start`, in order.
    - **reached:** one IntersectionObserver (threshold `0.15`, `root`). The first time a section intersects → `{ k:'reached', v, section }`, once per section per page load.
    - **active section:** a second IntersectionObserver with `rootMargin: '-40% 0px -60% 0px'` (a line at 40 % of the viewport height). The section crossing it is the active one. `onActiveChange` listeners get every change.
    - **enter:** when a section becomes active, start one `setTimeout(2000)`; cancel it if the active section changes first. When it fires and `document.visibilityState === 'visible'` → `{ k:'enter', v, section }`. Every new stay of 2 s or more sends again; the server caps at 300.
    - **click(target):** sends `{ k:'click', v, target }` only if `TRACK_TARGET_RE` matches; otherwise does nothing.
    - **active time:** see the algorithm below. Flush on `visibilitychange` (to hidden) and on `pagehide`, at most once per 1000 ms of `now()`, as `{ k:'time', v, ms: round(total), per }`, where `per` holds the rounded cumulative ms of each section with more than 0. Both values are cumulative per page load (the server keeps the max).
    - `destroy()` disconnects observers, clears the timer and removes listeners.

  Active-time algorithm (the only non-obvious part; no timers):

  ```ts
  // active = page visible AND an interaction (load, pointerdown, keydown, wheel, touchstart, scroll) in the last 60 s
  function accrue(t: number) {
    if (visible) {
      const end = Math.min(t, lastInteraction + 60_000)
      const d = Math.max(0, end - lastTick)
      total += d
      if (active) per[active] = (per[active] ?? 0) + d
    }
    lastTick = t
  }
  // call accrue(now()) BEFORE changing lastInteraction, visible or active; lastInteraction = lastTick = now() at creation
  ```
