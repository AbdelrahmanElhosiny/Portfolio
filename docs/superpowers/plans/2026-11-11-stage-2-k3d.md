> **For agentic workers:** Claude's code task is TDD (superpowers:executing-plans or subagent-driven-development). The owner's tasks are guide-and-review steps: Claude writes starter files and the guide, the owner finishes and runs them, and Claude reviews. Claude never runs `git commit` or `git push`.

**Goal:** The whole app (site, admin, api, Postgres) runs in a local k3d cluster from plain YAML that the owner wrote, at `http://portfolio.localhost:8080` and `http://admin.portfolio.localhost:8080`.

**Spec:** `docs/superpowers/specs/2026-11-11-portfolio-design.md` §3 (memory), §4 (picks), §5 (security basics: non-root, read-only root filesystem, NetworkPolicy), §7 (learning model), §8 stage 2.

**Depends on:** Plans 1–5 landed. The images from Plan 5 build for linux/arm64. Plan 1's `/healthz`, `/readyz`, SIGTERM close and `node dist/cli/migrate.js`. Plan 2's `node dist/cli/retention.js`.

## Reconsider before executing

- **`admin:init` prints the TOTP secret and recovery codes.** Pod logs of a Job keep them until the pod is deleted. Proposed: run it once with `kubectl run admin-init -it --rm --restart=Never ...` instead of a Job, so nothing is retained. The spec says "a Kubernetes Job"; the owner decides.
- **Local hostnames:** `portfolio.localhost` and `admin.portfolio.localhost`. `*.localhost` resolves to 127.0.0.1 in browsers and curl, so `/etc/hosts` stays untouched. Port 8080 is mapped to the k3d load balancer.
- **Env in k3d:** `COOKIE_SECURE=false` (plain http), `SITE_ORIGINS=http://portfolio.localhost:8080`, `PUBLIC_SITE_URL=http://portfolio.localhost:8080`, `TRUST_PROXY` left `false` until stage 5.
- **Secrets stay out of git** in this stage. They are created with `kubectl create secret ... --dry-run=client -o yaml` into a git-ignored file. SOPS arrives in stage 7.
- **Migration Job names are immutable.** Re-running needs `kubectl delete job migrate` first, or `ttlSecondsAfterFinished`. Helm hooks solve this in stage 7.
- **Memory limits below are first guesses.** They are measured with `kubectl top` and adjusted before stage 5, because the real node has 2 GB.
- **Check at execution:** the current k3d and k3s versions. Pin the k3s image to the same minor version stage 5 will install.
- **Port 8080 clash:** Plan 5's Compose also publishes the site on `8080`. Run `docker compose down` before `k3d cluster create`, or map k3d to another port (then update the `SITE_ORIGINS` / `PUBLIC_SITE_URL` values above).

## Task 1 (Claude, TDD): drain on shutdown

Plan 1 already closes the app and the pool on SIGTERM. Kubernetes keeps sending traffic for a few seconds after SIGTERM, until the endpoint is removed, so the API must fail readiness first and close afterwards.

**Files:** Modify `apps/api/src/server.ts`, `apps/api/src/config.ts`, `apps/api/src/app.ts` (readiness flag). Test `apps/api/test/shutdown.test.ts`.

**Produces:** env `SHUTDOWN_DELAY_MS` (default `5000`, `0` in tests); `app.beginShutdown(): void` sets the flag; `GET /readyz` → 503 `{"status":"shutting_down"}` once the flag is set; `server.ts` on SIGTERM calls `beginShutdown()`, waits `SHUTDOWN_DELAY_MS`, then closes the app and pool and exits 0.

- [ ] **Step 1: Write the failing tests:** `test('readyz 503 shutting_down after beginShutdown', ...)`, `test('healthz stays 200 during shutdown', ...)`, `test('SHUTDOWN_DELAY_MS parses; negative throws /SHUTDOWN_DELAY_MS/', ...)`.
- [ ] **Step 2:** `pnpm --filter @pf/api test`. Expected: FAIL.
- [ ] **Step 3: Implement.** Add `SHUTDOWN_DELAY_MS` to `.env.example`.
- [ ] **Step 4:** `pnpm test && pnpm typecheck`. Expected: PASS.
- [ ] **Step 5: Checkpoint.** The owner reviews and commits: `feat(api): drain readiness on SIGTERM`.
